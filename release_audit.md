## Personal server stage: evidence still required

The owner supplied the personal stage path `/users/xiaoxli/SignacShiny-stage/SignacShiny-chore-manuscript-ui-release`, personal R libraries, and four R files from that running stage. The reported 12/12 smoke result still requires its underlying scripts, logs, inputs, and outputs before it can be accepted as a complete release acceptance test. A separate browser session subsequently exercised the **running personal stage** with real PBMC data. Example import, QC plots and one PNG download, filtering, normalization, SVD/DepthCor, UMAP, clustering, Gene Activity Matrix, both RNA differential modes with CSV downloads, default SingleR annotation, and a genomic region plot produced outputs. GO ran but returned no enriched terms. The exact observations and remaining gaps are in `server_stage_browser_test_20261112.md`. The stage's relevant source is now merged, but the new Git commit itself has not yet undergone this runtime test.

A visible VS Code remote terminal initially showed a Motif traceback: `there is no package called 'TFBSTools'`. The owner subsequently reported adding the missing packages to personal R libraries. A new browser run on forwarded port 3848 completed Motif Enrichment (One vs Rest) with 633 table records and rendered a selected motif's sequence logo. It also completed an ALX3 Footprinting calculation, displayed the curve, and downloaded a valid 11,912,708-byte PNG. The first visible Motif `p.adjust` was 0.0609; the 633 records are not a claim of statistical significance. See `server_stage_browser_test_20261112.md`. Exact package paths remain unverified.

Four matching official source archives were downloaded and integrity checked outside the Git repository in `../signacshiny_official_r_packages/`: TFMPvalue 0.0.9 (CRAN archive), DirichletMultinomial 1.48.0, TFBSTools 1.44.0, and motifmatchr 1.28.0 (Bioconductor 3.20). The owner's later package-install report and successful browser calculations demonstrate functioning Motif dependencies in the personal stage, but the precise archive-to-install provenance and live namespace inventory have not been independently captured.

The inherited `server.R` initializes many analysis objects with `<<-` inside the Shiny server function. In R this can assign to a shared parent/global environment when no session-local binding exists, so concurrent sessions may interfere. This is a source-level risk, not a demonstrated failure in the single-session test. The repeated `reactiveValues()` initializers also obscure which slots are initialized; observed default workflows nevertheless ran. Correcting the shared-state design would touch many observers and requires a separate multi-session regression test against the actual stage source; it has not been silently refactored for v1.0.0. The existing `run_step()` measures elapsed time and before/after `lobstr::mem_used()` values when available; it does not measure peak process RSS. The reported ~2.23 GiB peak RSS from a separate smoke test must not be relabeled as a `run_step()` memory delta.
